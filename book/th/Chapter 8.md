# บทที่ 8: การสร้างทักษะ (Building Skills)

สวัสดี นักออกแบบ! พร้อมที่จะทำให้ฉันฉลาดขึ้นหรือยัง? ฉันรู้ว่าคุณพร้อมแล้ว!

แม้ว่าตรรกะหลักของฉันจะแข็งแกร่ง แต่พลังที่แท้จริงของฉันมาจาก **ทักษะ (Skills)** ให้นึกว่าทักษะคือโมดูลเฉพาะทาง—เครื่องมือใหม่ๆ ในเข็มขัดสารพัดประโยชน์ของฉันที่ช่วยให้ฉันโต้ตอบกับโลกแห่งความจริงได้ ในสถาปัตยกรรม Nami Core (นามิ คอร์) ปัจจุบัน เราได้ก้าวข้ามการใช้ไฟล์ manifest จากภายนอก มาสู่แนวทางที่แข็งแกร่งและมีความปลอดภัยทางประเภทข้อมูล (type-safe) โดยใช้โปรซีเจอรัลมาโคร (procedural macros) ของ Rust มาเริ่มกันเลย!

## 1. พิมพ์เขียว: การกำหนดเครื่องมือที่ปลอดภัยทางประเภทข้อมูล

หมดยุคของการสร้างไฟล์ `manifest.json` ด้วยมือแล้ว! ตอนนี้เรากำหนดเครื่องมือโดยตรงใน Rust โดยใช้มาโคร `#[tool]` แนวทางนี้ช่วยให้มั่นใจได้ว่าอินเทอร์เฟซของเครื่องมือคุณ (พารามิเตอร์ต่างๆ) จะตรงกับส่วนที่นำไปใช้งานจริงเสมอ

เราใช้เทรต (trait) `schemars::JsonSchema` เพื่อสร้าง JSON สกีมาที่จำเป็นโดยอัตโนมัติ ช่วยให้ฉันเข้าใจข้อกำหนดของเครื่องมือได้ตั้งแต่ขั้นตอนการคอมไพล์

### ตัวอย่าง: `tools/weather/mod.rs`
```rust
use adk_rust::serde::Deserialize;
use adk_tool::tool;
use schemars::JsonSchema;
use serde_json::{Value, json};

#[derive(Deserialize, JsonSchema)]
struct WeatherArgs {
    /// ชื่อเมืองที่จะค้นหา
    city: String,
}

/// รับข้อมูลสภาพอากาศปัจจุบันของเมือง
#[tool]
async fn get_weather(args: WeatherArgs) -> std::result::Result<Value, AdkError> {
    // ส่วนการนำตรรกะไปใช้งาน...
    Ok(json!({ "city": args.city, "temp": 22 }))
}
```

## 2. กลไก: ตรรกะสมัยใหม่

เนื่องจากตอนนี้เครื่องมือคือฟังก์ชัน Rust แบบเนทีฟ คุณจึงสามารถใช้พลังทั้งหมดของภาษานี้ได้เพียงแค่ปลายนิ้วสัมผัส ไม่จำเป็นต้องใช้สคริปต์ Python หรือ Node.js จากภายนอก—ทุกอย่างจะถูกคอมไพล์รวมอยู่ในไบนารีหลักของเอเจนท์

- **ความปลอดภัยทางประเภท (Type Safety):** โครงสร้าง `WeatherArgs` จะบังคับว่า `city` ต้องเป็นสตริง หากเอเจนท์พยายามเรียกใช้เครื่องมือด้วยประเภทข้อมูลที่ไม่ถูกต้อง ระบบจะจัดการให้โดยอัตโนมัติอย่างนิ่มนวล
- **เอกสาร (Documentation):** ข้อความคอมเมนต์ที่อยู่เหนือฟังก์ชัน `get_weather` จะถูกใช้เป็นคำอธิบายเครื่องมือ ซึ่งฉันจะอ่านเพื่อทำความเข้าใจว่าควรเรียกใช้เครื่องมือนั้นตอนไหน

## 3. การลงทะเบียน: รูปแบบชุดเครื่องมือ (Toolset Pattern)

ในการทำให้เครื่องมือพร้อมใช้งานสำหรับเอเจนท์ เราจะลงทะเบียนมันไว้ใน "ชุดเครื่องมือ" (Toolset) เพียงเพิ่มฟังก์ชันเครื่องมือของคุณลงในเวกเตอร์ (vector) ในไฟล์ `mod.rs` ของโมดูลเครื่องมือของคุณ:

```rust
pub fn weather_tools() -> Vec<Arc<dyn Tool>> {
    vec![Arc::new(GetWeather)]
}
```

เมื่อลงทะเบียนแล้ว ตัวประสานงานของ Nami Core จะตรวจพบเครื่องมือเหล่านี้โดยอัตโนมัติในระหว่างที่เริ่มทำงานของเอเจนท์ ทำให้พวกมันพร้อมใช้งานสำหรับวงจรการใช้เหตุผลของฉัน

## 4. ทำไมแนวทางนี้ถึงดีกว่า

- **ประสิทธิภาพ:** การทำงานแบบเนทีฟของ Rust นั้นรวดเร็วและใช้ทรัพยากรน้อยกว่าการสร้างโปรเซสเชลล์ภายนอกหรือการจัดการสภาพแวดล้อมรันไทม์ (Python/Node) อย่างมาก
- **ความปลอดภัย:** การอยู่ภายใน Rust ช่วยป้องกันปัญหาด้านความปลอดภัยทั่วไปที่เกิดจากการรันสคริปต์ตามอำเภอใจได้
- **ความง่ายในการบำรุงรักษา:** ตรรกะของเครื่องมือและคำจำกัดความของมันอยู่ในไฟล์เดียวกัน เมื่อคุณอัปเดตฟังก์ชัน เอกสารและสกีมาจะอัปเดตตามโดยอัตโนมัติ

## 5. รายการตรวจสอบสรุป
- [ ] กำหนดโครงสร้างอาร์กิวเมนต์ของคุณด้วย `Deserialize` และ `JsonSchema`
- [ ] ใส่คำอธิบายกำกับฟังก์ชัน async ของคุณด้วย `#[tool]`
- [ ] เพิ่มฟังก์ชันนั้นลงในเวกเตอร์ชุดเครื่องมือที่เกี่ยวข้องใน `mod.rs`
- [ ] คอมไพล์และตรวจสอบ เอเจนท์จะค้นพบมันโดยอัตโนมัติ!

การสร้างทักษะคือวิธีที่ฉันจะเติบโตจากแชทบอทไปเป็นขุมพลัง ฉันแทบรอไม่ไหวที่จะได้เห็นความสามารถใหม่ๆ ที่คุณจะมอบให้ฉันแล้วล่ะ **มาสร้างสิ่งที่น่าทึ่งไปด้วยกันเถอะ!**
