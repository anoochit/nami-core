# บทที่ 8: การสร้างทักษะ

สวัสดีเหล่าสถาปนิก! พร้อมที่จะทำให้ผมฉลาดขึ้นกว่าเดิมหรือยัง? ผมคิดไว้แล้วว่าคุณต้องพร้อม!

แม้ว่าตรรกะพื้นฐานของผมจะแข็งแกร่งอยู่แล้ว แต่พลังที่แท้จริงของผมมาจาก **Skills** (ทักษะ) ครับ ลองคิดว่าทักษะเหล่านี้คือโมดูลเฉพาะทาง—มันคือเครื่องมือใหม่ๆ ในเข็มขัดสารพัดประโยชน์ที่ช่วยให้ผมโต้ตอบกับโลกจริง ประมวลผลข้อมูลเฉพาะด้าน หรือทำให้เวิร์กโฟลว์ที่ซับซ้อนกลายเป็นเรื่องอัตโนมัติ ถ้าผมจินตนาการถึงมันได้ และคุณเขียนโค้ดมันออกมาได้ ผมก็ทำได้ทุกอย่างครับ!

ในบทนี้ เราจะมาดูวงจรชีวิตของการสร้างทักษะ ตั้งแต่จุดเริ่มต้นไปจนถึงความสามารถที่ใช้งานได้จริง ซึ่งผมสามารถค้นพบและเรียกใช้งานได้ทันที มาเริ่มกันเลย!

## 1. พิมพ์เขียว: การกำหนด Schema

ก่อนที่ผมจะเรียกใช้ทักษะใดๆ ผมจำเป็นต้องรู้ *อย่างชัดเจน* ว่ามันทำอะไรและต้องการข้อมูลอะไรบ้าง เราใช้ **JSON Schema** ในการกำหนด Interface ซึ่งทำหน้าที่เป็นสะพานเชื่อมระหว่างการใช้เหตุผลระดับสูงของผมกับการเขียนโปรแกรมของคุณ

ทุกๆ ทักษะจำเป็นต้องมีไฟล์ `manifest.json` เพื่อบอกผมว่า:
- **Name:** ทักษะนี้ชื่อว่าอะไร?
- **Description:** มันทำหน้าที่อะไร? (เขียนให้อธิบายได้ชัดเจนนะครับ! เพราะผมจะใช้ข้อมูลนี้ในการตัดสินใจว่าควรจะเรียกใช้ทักษะนี้เมื่อไหร่)
- **Parameters:** คุณต้องการข้อมูลอินพุตอะไรจากผมบ้าง?

### ตัวอย่าง: `weather_fetcher/manifest.json`
```json
{
 "name": "get_weather",
 "description": "ดึงข้อมูลสภาพอากาศปัจจุบันของเมืองที่ระบุ",
 "parameters": {
 "type": "object",
 "properties": {
 "city": {
 "type": "string",
 "description": "ชื่อเมือง เช่น 'Tokyo'"
 },
 "unit": {
 "type": "string",
 "enum": ["celsius", "fahrenheit"]
 }
 },
 "required": ["city"]
 }
}
```

## 2. เครื่องยนต์: การเขียนตรรกะ

Nami Core เป็นพหุภาษา (Polyglot) ครับ! ผมไม่เกี่ยงว่าคุณจะชอบ Python, Node.js หรือ Bash แบบดิบๆ—ตราบใดที่มันสามารถรับอินพุตและส่งคืนค่าเป็น JSON ได้ ผมรันได้หมด!

### ทางเลือก A: Python (มาตรฐานระดับ Gold Standard)
เหมาะอย่างยิ่งสำหรับการประมวลผลข้อมูลหรืองานที่เน้น AI
```python
# skills/weather_fetcher/main.py
import sys
import json

def run(city, unit="celsius"):
 # จินตนาการว่าตรงนี้คือการเรียกใช้ API จริงๆ!
 result = {"temp": 22, "condition": "Sunny", "city": city, "unit": unit}

 print(json.dumps(result))

if __name__ == "__main__":
 args = json.loads(sys.stdin.read())
 run(args.get("city"), args.get("unit"))
```

### ทางเลือก B: JavaScript/Node.js
ยอดเยี่ยมสำหรับการเชื่อมต่อผ่านเว็บ
```javascript
// skills/weather_fetcher/main.js

const fs = require('fs');
const input = JSON.parse(fs.readFileSync(0, 'utf8'));

console.log(JSON.stringify({
 status: "Success",
 data: `ขณะนี้อุณหภูมิ 22 องศาใน ${input.city}`
}));
```

### ทางเลือก C: Bash (เน้นความรวดเร็ว)
ดีที่สุดสำหรับคำสั่งระบบสั้นๆ
```bash
#!/bin/bash
# skills/sys_info/main.sh
echo "{\"uptime\": \"$(uptime -p)\", \"disk_usage\": \"$(df -h | grep '^/dev/')\"}"
```

## 3. การลงทะเบียนและการค้นหา

ผมใช้สิ่งที่ผมหาไม่เจอไม่ได้หรอกนะ! เพื่อให้ทักษะ "ถูกค้นพบได้" ให้นำไปวางไว้ในไดเรกทอรี `/skills` ที่กำหนดไว้ในรูทของ Nami Core

โครงสร้างไดเรกทอรีควรเป็นดังนี้:
```text
nami-core/
 skills/
 weather_fetcher/
 manifest.json
 main.py
 README.md <-- สำคัญมากสำหรับเอกสารประกอบ!
```

เมื่อผมเริ่มทำงาน (Initialize) ผมจะสแกนโฟลเดอร์ `/skills` ผมจะอ่านไฟล์ `manifest.json` และเพิ่มพวกมันลงใน **Action Library** (คลังการกระทำ) ของผม ในระหว่างการสนทนา หากคำขอของผู้ใช้ตรงกับคำอธิบายของทักษะ ผมจะสร้างอินพุต JSON ที่ถูกต้องและรันสคริปต์นั้นโดยอัตโนมัติ

## 4. เอกสารประกอบสำหรับ Agent

นี่แหละคือเคล็ดลับความอร่อย! อย่าเขียนให้แค่มนุษย์อ่าน—เขียนให้ **ผม** อ่านด้วย

ในไฟล์ `README.md` ของแต่ละทักษะ ให้ระบุส่วน **"Best Practices"** หรือ **"Context"** บอกผมว่า *เมื่อไหร่* ควรใช้ทักษะนี้ และมี *ข้อควรระวัง* ทั่วไปอะไรบ้าง

> **เคล็ดลับจาก Nami:** "ถ้าคุณกำลังสร้างทักษะที่ต้องเขียนข้อมูลลงฐานข้อมูล บอกผมในเอกสารด้วยว่าให้ตรวจสอบ 'id' ทุกครั้งก่อนส่งคำสั่งอัปเดต ผมจะจำมันไว้ตอนรันงานครับ!"

## 5. การทดสอบเวิร์กโฟลว์

ก่อนใช้งานจริง ให้ใช้ `nami-cli` เพื่อทดสอบทักษะแบบ **Isolation** (แยกส่วน):

```bash
nami skill test weather_fetcher --input '{"city": "San Francisco"}'
```

ถ้ามันส่งคืน JSON ที่ถูกต้อง ผมก็พร้อมลุยแล้ว!
