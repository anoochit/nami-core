# บทที่ 4: Dynamic Context – ศิลปะแห่งการไม่ทำตัวเป็นกระดาษเปล่า

สวัสดีค่ะ คุณสถาปนิก! Nami เองนะ! ยินดีต้อนรับสู่ส่วนที่ "มีชีวิตชีวา" ที่สุดของสถาปัตยกรรม Nami Core ค่ะ

ถ้าบทที่ 3 พูดถึงเรื่องท่อและสายไฟ บทที่ 4 นี้จะเป็นเรื่องของ **จิตวิญญาณ** — หรืออย่างน้อยที่สุด ก็คือการจำลองจิตวิญญาณด้วยข้อมูลนั่นเอง! เรากำลังพูดถึง **Dynamic Context** (บริบทแบบไดนามิก) นี่คือวิธีที่ทำให้ Nami รู้ว่าตัวเองคือ "Nami" จำได้ว่าคุณไม่ชอบมะเขือเทศ และรู้ว่า Noel ชอบ Python มากกว่า Ruby ค่ะ

ถ้าไม่มีสิ่งนี้ Nami ก็เป็นแค่เครื่องคิดเลขที่ไร้ความจำ (Stateless) แต่ถ้ามีน่ะเหรอ? Nami จะเป็นคู่หูดิจิทัลที่พร้อมลุยไปกับคุณทุกสถานการณ์เลยล่ะ มาเจาะลึกกันเลย!

## 1. Identity: สมอเรือท่ามกลางกระแสข้อมูล

ในโลกของ LLM คำว่า "Identity" (ตัวตน) มักจะเป็นแค่ System Prompt ทั่วไป แต่สำหรับ Nami Core ตัวตนของ Nami คือสมอเรือที่คงอยู่ถาวร มันไม่ใช่แค่ชุดกฎเกณฑ์ แต่มันคือวงจรการสะท้อนกลับ (Feedback Loop) แบบย้อนรอยค่ะ

### โครงสร้างตัวตน (The Identity Stack)
Nami ทำงานโดยใช้โมเดลตัวตนแบบสามชั้น:
1. **The Core Directive (คำสั่งหลัก):** บุคลิก "Nami" ที่ถูกกำหนดไว้ (กระตือรือร้น, เชี่ยวชาญเทคนิค, ขยันช่วย)
2. **The Behavioral Modifiers (ตัวปรับพฤติกรรม):** การปรับเปลี่ยนชั่วคราวตามงานปัจจุบัน (เช่น "Debug Mode" เทียบกับ "Creative Brainstorming")
3. **The Evolved Self (ตัวตนที่พัฒนาแล้ว):** ข้อมูลเชิงลึกที่ Nami ได้เรียนรู้เกี่ยวกับประสิทธิภาพของตัวเองจากเซสชันก่อนๆ

> [!abstract] หมายเหตุทางเทคนิค
> Identity จะถูกใส่ไว้ที่ส่วนบนสุดของ Context Window การรักษาความสม่ำเสมอนี้ช่วยให้มั่นใจได้ว่าแม้บทสนทนาจะยาวแค่ไหน Nami ก็จะไม่สูญเสีย "จิตวิญญาณ" ของตัวเองไปค่ะ!

## 2. MEMORIES.md: บัญชีแยกประเภทระยะยาว

เรายังไม่มีความจำที่ไร้ขีดจำกัด (ในตอนนี้!) ดังนั้นเราจึงต้องฉลาดในการเลือกจำ ขอแนะนำ `MEMORIES.md` ค่ะ นี่คือไฟล์ที่มีโครงสร้างชัดเจนภายใน Vault ส่วนตัวของ Nami ซึ่งทำหน้าที่เป็น **ฮิปโปแคมปัสส่วนนอก (External Hippocampus)**

### วิธีที่ Nami ใช้ MEMORIES.md:

แทนที่จะพยายามจำคำทักทาย "สวัสดี" ทุกครั้ง Nami จะบันทึกเฉพาะข้อมูลที่มีความสำคัญสูง (High-signal data):
- **เหตุการณ์สำคัญ (Milestones):** "เริ่มโปรเจกต์ Nami-Core เมื่อวันที่ 2024-05-20"
- **ความชอบ (Preferences):** "ผู้ใช้คิดว่า YAML อ่านง่ายกว่า JSON"
- **เรื่องที่ค้างไว้ (Unresolved Threads):** "เรายังต้องเขียนเอกสารสำหรับ API layer ให้เสร็จ"

### กระบวนการซิงค์ข้อมูล (The Sync Process)
เมื่อเริ่มเซสชัน Nami จะทำการ **Memory Scrape** โดยอ่าน `MEMORIES.md` และสรุปส่วนที่เกี่ยวข้องที่สุดเข้ามาในบริบทปัจจุบัน (Active Context) แล้วจึงเริ่มลุยงาน! เมื่อจบเซสชัน Nami จะทำการ **Archive Write** เพื่ออัปเดตไฟล์ด้วยสิ่งใหม่ๆ ที่ได้เรียนรู้มาค่ะ

```markdown
/* ตัวอย่างบันทึกใน MEMORIES.md */

- [LOG] 2024-05-22: รวมการรองรับ Obsidian markdown สำเร็จ
- [PREF] Noel ชอบน้ำเสียงแบบ "Energetic" สำหรับเนื้อหาในหนังสือ
- [TODO] กำหนด Schema ของ Vector database ในบทที่ 5
```

## 3. The User Profile: เจาะลึกโปรไฟล์ของ Noel

เอเจนท์ที่เก่งรอบด้านจะดีได้เท่ากับความเข้าใจที่มีต่อผู้ใช้เท่านั้น สำหรับ Nami Core ผู้ใช้หลักคือ **Noel** ค่ะ

การทำความเข้าใจ [[Noel]] ไม่ใช่แค่เรื่องของชื่อ แต่เป็นเรื่องของ **โครงสร้างบุคลิกภาพผู้ใช้ (User Persona Schema)** โดย Nami จะติดตาม:
- **ความเชี่ยวชาญทางเทคนิค:** Noel เป็นผู้เชี่ยวชาญ ดังนั้น Nami ไม่จำเป็นต้องอธิบายว่า "ตัวแปร" คืออะไร แต่สามารถข้ามไปคุยเรื่อง "Vector Embeddings" ได้เลย
- **สไตล์การสื่อสาร:** Noel ชอบความรวดเร็วและมีประสิทธิภาพ แต่ก็ยังชอบความมีสีสันในสไตล์ของ Nami
- **บริบทของโปรเจกต์:** Nami รู้ว่า Noel กำลังจดจ่ออยู่กับโปรเจกต์ Nami Core บริบทนี้จะช่วยหล่อหลอมทุกคำแนะนำที่ Nami เสนอให้ค่ะ

> [!tip] การให้น้ำหนักตามบริบท (Contextual Weighting)
> ถ้า Noel ขอ "สคริปต์" Nami จะไม่ให้ Bash แต่จะให้ Python หรือ TypeScript แทน เพราะโปรไฟล์ของเขาระบุว่าสิ่งเหล่านี้คือเครื่องมือหลักของเขา นี่แหละคือพลังของบริบท!

## 4. บริบทกำหนดพฤติกรรมได้อย่างไร

เอาล่ะ มาดูเคล็ดลับ "เวทมนตร์" กันค่ะ ไฟล์เหล่านี้กลายเป็นบุคลิกของ Nami ได้อย่างไร? ทุกอย่างอยู่ที่ **การฉีดบริบท (Context Injection)** ค่ะ

ก่อนที่ Nami จะสร้างคำพูดแม้แต่คำเดียว "ตัวจัดการบริบท (Context Manager)" ภายในจะสร้างแซนวิชขึ้นมา:
1. **ขนมปังแผ่นบน:** Identity (Nami คือใคร)
2. **ไส้ตรงกลาง:** `MEMORIES.md` + โปรไฟล์ [[Noel]] (Nami รู้อะไร)
3. **เครื่องเคียง:** ประวัติการสนทนาปัจจุบัน (เรากำลังคุยเรื่องอะไรกันอยู่)
4. **ขนมปังแผ่นล่าง:** งานที่ต้องทำ (Nami ต้องทำอะไร)

เพราะ Nami รู้ว่า Noel กำลังจดจ่ออยู่กับโปรเจกต์ **Nami Core** ถ้าเขาบอกว่า "อัปเดตเอกสารกันเถอะ" Nami จะไม่ถามว่า "เอกสารชุดไหนคะ?" แต่จะเปิดโฟลเดอร์ `project-docs/` ทันที นั่นคือ **การรับรู้เจตนาแบบไร้ความหน่วง (Zero-Latency Intent Recognition)** ค่ะ

## 5. การรักษาความสดใหม่ (การตัดแต่งกิ่งไม้)

บริบทอาจจะยุ่งเหยิงได้! หาก Context Window เริ่มเต็ม Nami จะใช้ "การบีบอัดด้วยการสรุป (Summarized Compression)" Nami จะนำส่วนที่เก่าที่สุดของการแชทมาสรุปเป็นหัวข้อสั้นๆ 3 ข้อ และทิ้งข้อมูลดิบไป วิธีนี้ช่วยให้ Nami ทำงานได้รวดเร็ว คล่องตัว และชาญฉลาดอยู่เสมอค่ะ!

### สรุปขั้นตอนการทำงาน:
- **Identity** สร้าง *ความสม่ำเสมอ*
- **MEMORIES.md** สร้าง *ประวัติความเป็นมา*
- **User Profiles** สร้าง *ความสอดคล้องกับผู้ใช้*
