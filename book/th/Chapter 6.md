# บทที่ 6: การปฏิบัติงานตามทักษะ (Skill-Based Execution) 

เอาล่ะ มาลงรายละเอียดเชิงลึกถึงกลไกการทำงานกันเลย! การคิดเป็นเรื่องที่ดี—อย่าเข้าใจผมผิดนะ ผมชอบการประมวลผลโลจิกที่ยอดเยี่ยม—แต่เอเจนท์อเนกประสงค์ (Generalist Agent) ที่ไม่สามารถ *ลงมือทำ* อะไรได้เลย ก็เป็นได้แค่เครื่องคิดเลขหน้าตาดีเท่านั้นแหละ

ใน **Nami Core** เราเชื่อมช่องว่างระหว่าง "การรู้" และ "การทำ" ผ่านสิ่งที่เรียกว่า **ทักษะ (Skills)** ถ้า LLM คือสมองของผม Skills ก็คือมือ ดวงตา และเครื่องมืออเนกประสงค์ของผม บทนี้จะเจาะลึกว่าเรานิยาม รวบรวม และเรียกใช้งานความสามารถเหล่านี้เพื่อโต้ตอบกับโลกจริงได้อย่างไร

## 1. "ทักษะ (Skill)" คืออะไร?

ทักษะคือฟังก์ชันที่แยกเป็นส่วนๆ (Discrete, Modular Function) ซึ่งช่วยให้ผมเชื่อมต่อกับสภาพแวดล้อมภายนอกได้ ไม่ว่าจะเป็นการอ่านไฟล์, การเรียกใช้งาน API หรือการสร้างรูปภาพ ทุกการกระทำจะถูกจัดเก็บในรูปแบบของ Skill

ในเชิงเทคนิค Skill คือการจับคู่กันระหว่าง **Schema + Logic**:
- **The Schema:** คำอธิบายในรูปแบบ JSON (มักเป็นไปตามรูปแบบ Tool/Function calling ของ OpenAI) ที่บอกผมว่า Skill นั้นทำ *อะไร* และต้องการ *อาร์กิวเมนต์ (Arguments)* อะไรบ้าง
- **The Logic:** โค้ดที่อยู่เบื้องหลัง (Python, JavaScript หรือ Bash) ที่ทำหน้าที่รันงานนั้นจริงๆ

## 2. การรวมกลุ่ม: แนวคิดเรื่อง "ชุดเครื่องมือ (Toolset)"

เราไม่ได้แค่โยนฟังก์ชันดิบๆ ใส่ระบบไปเฉยๆ! เพื่อให้พื้นที่บริบท (Context Window) ของผมสะอาดและประมวลผลได้อย่างมีประสิทธิภาพ เราจึงใช้ระบบ **ชุดเครื่องมือทักษะ (Skill Toolsets)**

การรวมกลุ่มช่วยให้ผมโหลด "โปรไฟล์" เฉพาะทางตามงานที่ได้รับ เราจะพกหัวแร้งไปงานแข่งอ่านบทกวีทำไมจริงไหมล่ะ?

### Toolset Manifest
ทุกชุดเครื่องมือจะมีไฟล์ `manifest.yaml` ที่กำหนดขอบเขตการทำงานของมัน

```yaml
toolset_id: "dev_ops_plus"
version: "1.2.0"
capabilities:
 - file_write
 - git_commit
 - docker_status
 - log_parser
dependencies: ["python-docker-sdk", "gitpython"]
```

ด้วยการจัดกลุ่มเหล่านี้ ตัวประสานงาน (Orchestrator) ของ **Nami Core** สามารถสลับความสามารถที่เปิดใช้งานของผมได้ทันที หากคุณบอกผมว่า "Deploy แอปนี้ที" ผมจะสลับไปใช้ชุดเครื่องมือ `DevOps` แต่ถ้าคุณบอกว่า "เขียนรายงานให้หน่อย" ผมจะเปลี่ยนไปใช้ `OfficeSuite` แทน

## 3. กลไกการสั่งการ: จากเจตนาสู่การกระทำ

ผมเรียกใช้งานทักษะได้อย่างไร? มันไม่ใช่เวทมนตร์ แต่มันคือการประสานงาน 3 ขั้นตอน:

### ก. การรับรู้เจตนา (Intent Recognition)

เมื่อคำสั่ง (Prompt) เข้าสู่ระบบ **Intent Engine** จะวิเคราะห์คำขอเพื่อค้นหาคำกริยาและเป้าหมาย
*ข้อมูลนำเข้า (Input):* "เฮ้ Nami ช่วยหา log ล่าสุดแล้วสรุปข้อผิดพลาดให้หน่อย"
*เจตนา (Intent):* `ACTION: READ_LOGS`, `ACTION: SUMMARIZE`

### ข. การจับคู่ Schema (Schema Matching)
ผมจะค้นหาในชุดเครื่องมือที่ใช้งานอยู่เพื่อหา Skill ที่มีคำอธิบายตรงกับเจตนา
- **พบสิ่งที่ตรงกัน:** `fetch_system_logs(lines: int, level: string)`
- **การดึงพารามิเตอร์:** ผมจะดึงข้อมูลที่จำเป็นจากคำสั่งของคุณ (เช่น `lines=100`, `level='ERROR'`)


### ค. ลูปการทำงาน (JIT Execution)
Core จะรัน Skill ใน **สภาพแวดล้อมจำลอง (Sandbox)** ผมไม่ได้รันโค้ดบนระบบของคุณโดยตรง—ความปลอดภัยต้องมาก่อน!

1. **Call:** ผมส่งสัญญาณเรียกใช้เครื่องมือ
2. **Execution:** ระบบรันฟังก์ชันนั้น
3. **Return:** ผลลัพธ์ (JSON หรือ String) จะถูกส่งกลับเข้าสู่บริบทของผม
4. **Conclusion:** ผมตีความผลลัพธ์และให้คำตอบแก่คุณ!

## 4. การค้นหาทักษะแบบไดนามิก (Dynamic Skill Discovery)

นี่คือส่วนที่เจ๋งที่สุด! Nami Core รองรับ **การโหลดทักษะแบบทันเวลา (Just-In-Time - JIT)** หากผมตระหนักว่าไม่มีเครื่องมือที่จำเป็น ผมสามารถสอบถามไปยัง `Skill Library` ทั้งในเครื่องหรือบนคลาวด์ได้

```python
if context.requires("search") and not self.has_skill("web_search"):
 self.request_skill_load("search_provider_brave")
```

สิ่งนี้ทำให้ผมทำงานได้อย่างรวดเร็วและเบาตัว ผมไม่จำเป็นต้องเป็นทุกอย่างในคราวเดียว ผมแค่ต้องสามารถ *กลายเป็น* สิ่งที่งานนั้นต้องการได้ก็พอ

## 5. การจัดการข้อผิดพลาดและการแก้ไขตัวเอง

ทักษะอาจล้มเหลวได้ API อาจล่ม หรือสิทธิ์การเข้าถึงดิสก์อาจมีปัญหา ใน Nami Core ความล้มเหลวของทักษะไม่ใช่การแครช แต่มันคือ **ลูปการตอบกลับ (Feedback Loop)** หาก Skill ส่งคืนข้อผิดพลาด ผลลัพธ์นั้นจะถูกส่งกลับมาให้ผมในฐานะ "การสังเกตการณ์ (Observation)"

- **Observation:** `Error: Permission Denied at /var/log/`
- **ตรรกะของ Nami:** "โอ๊ะ ผมเข้าถึงส่วนนั้นไม่ได้ เดี๋ยวผมลองใช้ `sudo_read` หรือขอสิทธิ์การเข้าถึงระดับสูงจากผู้ใช้ดู"

## บทสรุป

ทักษะเปลี่ยน LLM ให้กลายเป็นเอเจนท์ (Agent) ด้วยการรวมพวกมันเข้าเป็นชุดเครื่องมือและการใช้กลไกการสั่งการผ่าน Schema ที่แข็งแกร่ง Nami Core จึงทำงานได้รวดเร็ว ปรับเปลี่ยนได้ และมีความสามารถที่น่าทึ่ง
