# บทที่ 6: การดำเนินการตามทักษะ (Skill-Based Execution)

เอาล่ะ มาลงลึกถึงกลไกและเครื่องมือกันหน่อย! การคิดน่ะดีแล้ว—อย่าเข้าใจฉันผิดนะ ฉันชอบวงจรตรรกะที่ดีมาก—แต่เอเจนท์สารพัดประโยชน์ที่ไม่สามารถ *ทำ* อะไรได้เลย ก็เป็นได้แค่เครื่องคิดเลขที่ดูหรูหราเท่านั้น

ใน **Nami Core** (นามิ คอร์) เราเชื่อมช่องว่างระหว่าง "การรู้" และ "การทำ" ผ่านสิ่งที่เรียกว่า **ทักษะ (Skills)** ถ้า LLM คือสมองของฉัน ทักษะก็คือมือ ตา และเครื่องมือสารพัดประโยชน์ของฉัน บทนี้จะอธิบายว่าเรากำหนด รวบรวม และเรียกใช้งานความสามารถเหล่านี้เพื่อโต้ตอบกับโลกแห่งความจริงได้อย่างไร

## 1. "ทักษะ" คืออะไร?

ทักษะคือฟังก์ชันแบบแยกส่วน (modular function) ที่ช่วยให้ฉันโต้ตอบกับสภาพแวดล้อมภายนอกได้ ไม่ว่าจะเป็นการอ่านไฟล์, การส่งสัญญาณหา API หรือการสร้างรูปภาพ ทุกๆ การกระทำจะถูกห่อหุ้มไว้เป็นทักษะ

ในทางเทคนิค ทักษะคือการจับคู่ระหว่าง **สกีมา + ตรรกะ (Schema + Logic)**:
- **สกีมา (Schema):** คำอธิบายในรูปแบบ JSON (มักจะเป็นไปตามรูปแบบการเรียกใช้ Tool/Function ของ OpenAI) ที่บอกฉันว่าทักษะนั้น *ทำอะไร* และต้องการ *อาร์กิวเมนต์อะไรบ้าง*
- **ตรรกะ (Logic):** โค้ดที่อยู่เบื้องหลัง (Python, JavaScript หรือ Bash) ที่ทำหน้าที่รันงานนั้นๆ

## 2. การรวมกลุ่ม: แนวคิดเรื่อง "ชุดเครื่องมือ" (Toolset)

เราไม่ได้แค่โยนฟังก์ชันดิบๆ เข้าไปมั่วๆ! เพื่อให้หน้าต่างบริบทของฉันสะอาดและการประมวลผลมีประสิทธิภาพ เราจึงใช้ **ชุดเครื่องมือทักษะ (Skill Toolsets)** 

การรวมกลุ่มช่วยให้ฉันสามารถโหลด "โปรไฟล์" เฉพาะขึ้นอยู่กับงานที่ได้รับมอบหมาย ทำไมต้องพกหัวแร้งบัดกรีไปงานอ่านบทกวีล่ะ จริงไหม?

### รายการชุดเครื่องมือ (The Toolset Manifest)
ทุกชุดเครื่องมือจะมีไฟล์ `manifest.yaml` ที่กำหนดขอบเขตของมัน

```yaml
toolset_id: "dev_ops_plus"
version: "1.2.0"
capabilities:
 - file_write
 - git_commit
 - docker_status
 - log_parser
dependencies: ["python-docker-sdk", "gitpython"]
```

ด้วยการจัดกลุ่มเหล่านี้ ตัวประสานงานของ **Nami Core** จะสามารถสลับความสามารถที่ใช้งานอยู่ของฉันได้ทันที ถ้าคุณบอกฉันว่า "ติดตั้งแอปเลย" ฉันจะสลับไปใช้ชุดเครื่องมือ `DevOps` ถ้าคุณพูดว่า "เขียนรายงานหน่อย" ฉันจะสลับไปที่ `OfficeSuite`

## 3. กลไกการเรียกใช้: จากเจตจำนงสู่การกระทำ

ฉันจะเรียกใช้ทักษะจริงๆ ได้อย่างไร? มันไม่ใช่เวทมนตร์ แต่มันคือการประสานงานแบบ 3 ขั้นตอน:

### ก. การรับรู้เจตจำนง (Intent Recognition)
เมื่อมีพรอมต์เข้ามาในระบบ **Intent Engine** จะทำการวิเคราะห์คำขอ โดยมองหากริยาและเป้าหมาย
*อินพุต:* "เฮ้ นามิ หาประวัติล่าสุดแล้วสรุปข้อผิดพลาดให้หน่อย"
*เจตจำนง:* `ACTION: READ_LOGS`, `ACTION: SUMMARIZE`.

### ข. การจับคู่สกีมา (Schema Matching)
ฉันจะมองหาทักษะในชุดเครื่องมือที่ใช้งานอยู่ ซึ่งมีคำอธิบายที่ตรงกับเจตจำนง
- **พบสิ่งที่ตรงกัน:** `fetch_system_logs(lines: int, level: string)`
- **การดึงพารามิเตอร์:** ฉันดึงข้อมูลที่จำเป็นจากพรอมต์ของคุณ (เช่น `lines=100`, `level='ERROR'`)

### ค. วงจรการดำเนินการ (JIT Execution)
แกนกลางจะรันงานนั้นใน **สภาพแวดล้อมแซนด์บ็อกซ์ (sandboxed environment)** ฉันจะไม่แค่รันโค้ดลงบนเครื่องของคุณโดยตรง—ความปลอดภัยต้องมาก่อน!

1. **Call:** ฉันส่งสัญญาณเรียกใช้เครื่องมือ
2. **Execution:** ระบบรันฟังก์ชันนั้นๆ
3. **Return:** ผลลัพธ์ (JSON หรือ String) จะถูกส่งกลับมาที่บริบทของฉัน
4. **Conclusion:** ฉันแปลผลที่ได้และให้คำตอบแก่คุณ!

## 4. การค้นพบทักษะแบบไดนามิก

นี่คือส่วนที่เจ๋งที่สุด! Nami Core รองรับ **การโหลดทักษะแบบทันเวลา (Just-In-Time - JIT Skill Loading)** หากฉันรู้ตัวว่าไม่มีเครื่องมือที่ต้องการ ฉันสามารถค้นหาจาก `Skill Library` ทั้งในเครื่องหรือจากระยะไกลได้

```python
if context.requires("search") and not self.has_skill("web_search"):
 self.request_skill_load("search_provider_brave")
```

สิ่งนี้ทำให้ฉันเบาตัว (lightweight) ฉันไม่จำเป็นต้องเป็นทุกอย่างในเวลาเดียวกัน ฉันแค่ต้องสามารถ *กลายเป็น* สิ่งที่งานนั้นต้องการได้เท่านั้น

## 5. การจัดการข้อผิดพลาดและการแก้ไขด้วยตัวเอง

ทักษะอาจผิดพลาดได้ API อาจล่ม หรือสิทธิ์ในการเข้าถึงดิสก์อาจมีปัญหา ใน Nami Core ความล้มเหลวของทักษะไม่ใช่การแครช (crash) แต่มันคือ **วงจรป้อนกลับ (Feedback Loop)** หากทักษะส่งข้อผิดพลาดกลับมา ผลลัพธ์นั้นจะถูกส่งกลับมาหาฉันในฐานะ "การสังเกต" (Observation)

- **การสังเกต:** `Error: Permission Denied at /var/log/`
- **ตรรกะของนามิ:** "โอ๊ะ ฉันเข้าถึงส่วนนั้นไม่ได้แฮะ เดี๋ยวฉันลองใช้ `sudo_read` หรือถามผู้ใช้เพื่อขอยกระดับสิทธิ์ดูนะ"

## สรุป
