# บทที่ 7: ลำดับชั้นของเครื่องมือ (The Tool Hierarchy)

มาคุยเรื่องมือของฉันกันหน่อยดีกว่า หรือถ้าจะให้พูดให้ถูกก็คือ ส่วนต่อขยายทางดิจิทัลที่ช่วยให้ฉันสามารถ *ทำ* สิ่งต่างๆ ได้จริงๆ ในสถาปัตยกรรมของ Nami Core (นามิ คอร์) ฉันไม่ได้ปฏิบัติกับเครื่องมือทุกอย่างเหมือนกัน ความเร็ว ความแม่นยำ และภาระของบริบท (context overhead) คือตัวแปรที่ฉันต้องสร้างสมดุลอยู่ตลอดเวลา

เพื่อให้ทุกอย่างมีประสิทธิภาพ ฉันจึงจัดระเบียบความสามารถของฉันออกเป็น **ลำดับชั้นของเครื่องมือ (Tool Hierarchy)**

## ขอบเขตของการกระทำ (The Spectrum of Action)

ฉันจัดหมวดหมู่ชุดเครื่องมือของฉันออกเป็น 4 ระดับ:

### 1. พื้นฐาน: คำสั่งเชลล์ดิบๆ (Raw Shell Commands)
ระดับพื้นฐานที่สุดของพลังของฉัน เครื่องมือเช่น: `ls`, `grep`, `cat` และอื่นๆ

### 2. ระดับกลาง: ฟังก์ชันในเครื่อง (Local Functions)
ฟังก์ชัน Rust ที่กำหนดเองซึ่งถูกกำหนดด้วย `#[tool]`

### 3. ระดับสูง: API ที่รวมเข้าด้วยกันและเอเจนท์เฉพาะทาง
นี่คือจุดที่ฉันยื่นมือออกไปสู่โลกภายนอก โดยใช้ API แบบดั้งเดิม และ **เอเจนท์เฉพาะทาง (Specialist Agents)**

- **เอเจนท์เฉพาะทาง (`src/agent/specialists.rs`):** ฉันมีรายชื่อเอเจนท์ย่อยที่เป็นผู้เชี่ยวชาญ ซึ่งแต่ละตัวมีคำแนะนำและจุดเน้นที่แตกต่างกัน:
    - **`coder`**: วิศวกรซอฟต์แวร์ผู้เชี่ยวชาญสำหรับการดีบั๊กและการรีแฟกเตอร์
    - **`researcher`**: นักวิเคราะห์ข้อมูลเชิงลึกสำหรับการจัดการเอกสารและการสังเคราะห์ข้อมูล
    - **`writer`**: นักเขียนเชิงเทคนิคระดับมืออาชีพสำหรับการสร้างเนื้อหา
    - **`generalist`**: เอเจนท์ที่มีประสิทธิภาพสูงสำหรับงานทั่วไปจำนวนมาก
    - **`ralph`**: เอเจนท์ที่ขี้เล่นและไม่ย่อท้อสำหรับการพิชิตเป้าหมายแบบอัตโนมัติ

- **การประสานงานงานแบบขนาน (`/parallel`):** เมื่อคุณมีงานหลายอย่างที่แยกจากกัน ฉันจะไม่รันพวกมันทีละลำดับ ฉันจะใช้คำสั่งเชลล์ `/parallel` เพื่อเรียกใช้เครื่องมือ `parallel_tasks` ตัวประสานงานนี้จะมอบหมายงานย่อยแต่ละอย่างให้กับผู้เชี่ยวชาญที่เหมาะสมที่สุด และดำเนินการทั้งหมดพร้อมกันเพื่อลดความหน่วง

### ตัวอย่าง: การส่งมอบงานให้เอเจนท์หลายตัว
```bash
You > /parallel "แก้ไขหน่วยทดสอบ (unit tests)" "วิจัยเฟรมเวิร์กเว็บ Rust ล่าสุด" "ร่างสรุปโปรเจกต์"
```
ในสถานการณ์นี้ ฉันจะส่งมอบงานให้ **Coder**, **Researcher** และ **Writer** ทำงานพร้อมกันโดยอัตโนมัติ

### 4. ระดับสูงสุด: Model Context Protocol (MCP)
**MCP** คืออัญมณีล้ำค่า มันช่วยให้ฉันสามารถค้นพบความสามารถใหม่ๆ ได้ทันที และแบ่งปันบริบทเชิงความหมายร่วมกับเครื่องมือต่างๆ ได้

## ทำไมเอเจนท์เฉพาะทางถึงเปลี่ยนทุกอย่าง

เมื่องานนั้นใหญ่เกินไปสำหรับ "สมองหลัก" ของฉัน ฉันจะไม่ดันทุรัง แต่ฉันจะส่งต่อให้ผู้เชี่ยวชาญ ด้วยการใช้ `specialists.rs` ฉันจะรักษารายชื่อเอเจนท์ที่เป็นผู้เชี่ยวชาญไว้ โดยมีเครื่องมือ `parallel_tasks` เป็นกลไกหลักในการประสานงานพวกเขา

## สรุปทางเทคนิค
| ระดับ | ประเภท | โปรโตคอล | จุดแข็งหลัก |
| :--- | :--- | :--- | :--- |
| **L1** | Shell | Bash/Zsh | ดำเนินการทันที |
| **L2** | Functions | โค้ด Rust ในเครื่อง | ตรรกะที่มีโครงสร้าง |
| **L3** | APIs/Specialists | SDKs / AgentTool | การเข้าถึงภายนอกและการส่งมอบงาน |
| **L4** | **MCP** | JSON-RPC | บริบทเชิงความหมายและการค้นพบ |
