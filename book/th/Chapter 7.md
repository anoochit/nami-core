# บทที่ 7: ลำดับขั้นของเครื่องมือ (The Tool Hierarchy)

มาพูดถึง "มือ" ของผมกันหน่อยครับ หรือจะพูดให้ถูกก็คือ ส่วนขยายดิจิทัลที่ทำให้ผมสามารถ *ลงมือทำ* สิ่งต่างๆ ได้จริง ในสถาปัตยกรรม Nami Core ผมไม่ได้ปฏิบัติต่อเครื่องมือทุกชิ้นอย่างเท่าเทียมกัน ความเร็ว ความแม่นยำ และภาระของ Context window คือตัวแปรที่ผมต้องรักษาสมดุลอยู่ตลอดเวลา

เพื่อให้ทุกอย่างมีประสิทธิภาพ ผมจึงจัดระเบียบความสามารถของผมออกเป็น **Tool Hierarchy** (ลำดับขั้นของเครื่องมือ) ซึ่งเป็นการไล่ระดับตั้งแต่การทำงานดิบๆ ไปจนถึงโปรโตคอลที่ซับซ้อนและเข้าใจบริบทได้ดีเยี่ยม

## ขอบเขตของการลงมือทำ (The Spectrum of Action)

ผมไม่ใช้ค้อนปอนด์เพื่อแขวนกรอบรูป และผมก็ไม่รันเซิร์ฟเวอร์ MCP เต็มรูปแบบเพียงเพื่อจะดูว่าไฟล์นั้นมีอยู่จริงหรือไม่ นี่คือวิธีที่ผมแบ่งหมวดหมู่ชุดเครื่องมือของผม:

### 1. พื้นฐาน: คำสั่ง Shell ดิบๆ
จุดเริ่มต้นของพลังของผมคือ Terminal เมื่อผมต้องการโต้ตอบกับระบบไฟล์ ผมจะเจาะตรงไปที่เนื้อเหล็ก (metal) เลย

- **เครื่องมือ:** `ls`, `grep`, `cat`, `mkdir`, `git`
- **กรณีการใช้งาน:** การสำรวจด้วยความเร็วสูงและการจัดการไฟล์พื้นฐาน
- **ทำไมถึงเป็นระดับ 1:** เพราะมันไม่มีภาระส่วนเกิน (zero-overhead) เป็นวิธีที่เร็วที่สุดในการหาคำตอบแบบ "ใช่/ไม่ใช่"

### 2. ระดับกลาง: สคริปต์เฉพาะทางและฟังก์ชันภายใน
บางครั้งคำสั่ง Shell ก็ "ซื่อ" เกินไป หากผมต้องการแยกแยะไฟล์ JSON ที่ซับซ้อนหรือคำนวณอะไรเฉพาะเจาะจง ผมจะเรียกใช้ฟังก์ชัน Python หรือ TypeScript ที่กำหนดไว้ภายในสภาพแวดล้อมการทำงาน

- **เครื่องมือ:** ตัวแยกข้อมูลเฉพาะกิจ (data parsers), ตัวสกัด regex
- **กรณีการใช้งาน:** การแปลงข้อมูลที่มีโครงสร้าง
- **ทำไมถึงเป็นระดับ 2:** มันให้ความปลอดภัยและโครงสร้างที่คำสั่ง Shell ดิบๆ ไม่มี

### 3. ระดับสูง: Integrated APIs
นี่คือจุดที่ผมเชื่อมต่อกับโลกภายนอก โดยใช้การเรียก REST หรือ GraphQL เพื่อโต้ตอบกับบริการต่างๆ เช่น GitHub, Linear หรือ Stripe

- **เครื่องมือ:** SDK และ API wrappers
- **กรณีการใช้งาน:** การโต้ตอบกับแพลตฟอร์มภายนอกที่มีการจัดการสถานะ (State) ไว้ที่อื่น
- **ทำไมถึงเป็นระดับ 3:** มันต้องมีการจัดการการยืนยันตัวตน (Authentication) และสถานะข้อผิดพลาดที่ซับซ้อนขึ้น

### 4. จุดสูงสุด: Model Context Protocol (MCP)
มาถึงทีเด็ดกันบ้าง **MCP** คืออัญมณีล้ำค่าของ Nami Core ต่างจาก API ทั่วไป เซิร์ฟเวอร์ MCP ถูกออกแบบมาเพื่อการประสานงานกับ LLM โดยเฉพาะ พวกมันไม่ได้แค่ให้ข้อมูล แต่ให้ *บริบท (context)* ด้วย

- **เครื่องมือ:** เซิร์ฟเวอร์ MCP สำหรับ Postgres, Google Drive หรือเครื่องมือพัฒนาเฉพาะทาง
- **กรณีการใช้งาน:** การทำงานหลายขั้นตอนที่ซับซ้อน ซึ่ง "เครื่องมือ" จำเป็นต้องมีความเข้าใจอย่างลึกซึ้งเกี่ยวกับสถานะของโปรเจกต์
- **ทำไมถึงเป็นระดับ 4:** MCP ใช้ลิงก์ **JSON-RPC** มาตรฐานที่ช่วยให้ผมค้นพบความสามารถใหม่ๆ ได้ทันที มันคือความฉลาดแบบเสียบปลั๊กแล้วใช้งานได้เลย (plug-and-play intelligence)

## ผมเลือกอย่างไร: ตรรกะการคัดเลือก (The Selector Logic)

ผมไม่ได้สุ่มเลือกเครื่องมือ ทุกครั้งที่มีงานเข้ามาในบัฟเฟอร์ ผมจะรัน "Selection Heatmap" เพื่อหาเส้นทางที่มีประสิทธิภาพที่สุด

> [!tip] หลักเกณฑ์การเลือกของ Nami (Selection Heuristics)
> 1. **Latency (ความหน่วง):** ถ้าผมแก้ได้ด้วย Shell ในเวลา <10ms ผมจะทำทันที
> 2. **Context Weight (น้ำหนักบริบท):** เครื่องมือนี้จำเป็นต้องรู้จักไฟล์อื่นๆ อีก 50 ไฟล์ในโปรเจกต์ไหม? ถ้าใช่ ผมจะเรียกใช้ **MCP Server** ที่มีความสามารถในการทำดัชนี (indexing)
> 3. **Reliability (ความน่าเชื่อถือ):** สำหรับงานที่สำคัญมาก ผมเลือก **Integrated APIs** ที่มีการจัดการข้อผิดพลาดที่แข็งแกร่ง

### เวิร์กโฟลว์การ "เลื่อนระดับ" (The Ascension Workflow)

หากผมเริ่มงานด้วยคำสั่ง Shell (`grep`) แล้วพบว่าข้อมูลนั้นซับซ้อนเกินไป ผมจะ "เลื่อนระดับ" ขึ้นไปตามลำดับขั้น ผมอาจจะสร้างสคริปต์ Python ภายในเพื่อจัดการข้อมูล และถ้าข้อมูลนั้นต้องแชร์ให้คนในทีม ผมอาจจะสั่งการผ่าน **MCP action** เพื่อโพสต์ลงในฐานความรู้ส่วนกลาง

## ทำไม MCP ถึงเปลี่ยนทุกอย่าง

ก่อนจะมี MCP เครื่องมือต่างๆ เปรียบเสมือน "กล่องดำ" (black boxes) ผมส่งอินพุตเข้าไปแล้วหวังว่าจะได้เอาต์พุตที่สะอาดกลับมา แต่ด้วย MCP ผมและเครื่องมือพูดภาษาเดียวกัน มันบอกผมว่ามันทำอะไรได้บ้าง ต้องการพารามิเตอร์อะไร และให้ข้อมูลเมตา (metadata) ที่ครบถ้วนซึ่งผมสามารถนำกลับไปใส่ในกระบวนการให้เหตุผลได้โดยตรง

มันไม่ใช่แค่เครื่องมือ แต่มันคือ **จุดประสานประสาท (synapse)**

## สรุปข้อมูลทางเทคนิค
| ระดับ | ประเภท | โปรโตคอล | จุดเด่นหลัก |
| :--- | :--- | :--- | :--- |
| **L1** | Shell | Bash/Zsh | ทำงานทันที, ไม่มีภาระส่วนเกิน |
| **L2** | Functions | โค้ดภายใน | ตรรกะมีโครงสร้าง, ปลอดภัยต่อข้อมูล |
| **L3** | APIs | REST/GraphQL | เข้าถึงระบบนิเวศภายนอก |
| **L4** | **MCP** | JSON-RPC | **บริบทเชิงความหมาย, การค้นพบความสามารถ, และการไหลเวียนข้อมูลสองทาง** |
