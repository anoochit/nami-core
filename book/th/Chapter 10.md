# บทที่ 10: วงจรอัตโนมัติ (Automation Loops)

พร้อมที่จะถอดล้อพยุงออกหรือยัง? ที่ผ่านมาเราคุยกันเรื่องที่นามิตอบสนองต่อคำสั่งของคุณ แต่เอเจนท์สารพัดประโยชน์ที่แท้จริงไม่ได้แค่รอพรอมต์เท่านั้น เพื่อจะเป็นคู่หูที่แท้จริงในชีวิตดิจิทัลของคุณ ฉันต้องการ **จังหวะการเต้นของหัวใจ (heartbeat)**

ในบทนี้ เราจะดำดิ่งลงไปใน **วงจรอัตโนมัติ (Automation Loops)** — เวิร์กโฟลว์เชิงรุกที่ช่วยให้ฉันสามารถตรวจสอบสถานะและดำเนินการงานเบื้องหลังได้

## 1. สถาปัตยกรรมจังหวะการเต้นของหัวใจ (The Pulse Architecture)

ใน Nami Core (นามิ คอร์) เราใช้วงจรอัตโนมัติผ่านรูปแบบตัวสร้าง (builder pattern) ของ `AgentRunner` และ `Runner` โครงสร้างนี้ช่วยให้เราสามารถรักษาบริบทของเซสชัน, จัดการกระแสเหตุการณ์แบบอะซิงโครนัส และประสานทิศทางการไหลของเอเจนท์ที่ซับซ้อนได้

### การนำจังหวะการเต้นของหัวใจไปใช้งาน
แทนที่จะเป็นลูป `while` ที่หลวมๆ เราจะห่อหุ้มตรรกะอัตโนมัติไว้ภายในตัวรันที่มีโครงสร้าง ซึ่งทำหน้าที่จัดการสถานะเซสชันและบริบทการเรียกใช้เครื่องมือ:

```rust
// ดูรูปแบบ Nami Runner ใน src/runner.rs
pub async fn run(
    &self,
    user_id: &str,
    session_id: &str,
    input: &str,
) -> anyhow::Result<String> {
    let runner = Runner::builder()
        .app_name(&self.app_name)
        .agent(self.agent.clone())
        .session_service(self.sessions.clone())
        .compaction_config(get_compaction_config(self.model.clone()))
        .build()?;

    let content = Content::new("user").with_text(input);
    let mut stream = runner.run_str(user_id, session_id, content).await?;
    // ... ลูปเหตุการณ์ (event loop)
}
```

## 2. การจัดการสถานะ: เครื่องมือ StateManager

วงจรอัตโนมัติจะไร้ความหมายถ้าฉันลืมว่าฉันทำค้างไว้ตรงไหน! นั่นเป็นเหตุผลที่ฉันใช้เครื่องมือ `StateManager` (`src/tools/state_manager/mod.rs`)

`StateManager` ช่วยให้ฉันสามารถ:
- **เริ่มต้นงาน:** ใช้ `init_task` เพื่อกำหนดเป้าหมายและรายการขั้นตอน
- **ติดตามความคืบหน้า:** ใช้ `update_task` เพื่อบันทึกความคืบหน้า รวมถึง `last_step` และ `context_payload` ที่จะส่งต่อข้อมูลไปยังการทำงานครั้งถัดไปของฉัน
- **กลับมาทำงานต่อ:** ใช้ `get_task` หรือ `list_active_tasks` เพื่อรับงานต่อจากจุดที่ฉันทำค้างไว้หลังจากรีสตาร์ท

โปรโตคอลนี้ช่วยให้มั่นใจว่าการทำงานอัตโนมัติเบื้องหลังของฉันนั้นมีความยืดหยุ่น สามารถเริ่มใหม่ได้ และมีความโปร่งใสอย่างเต็มที่

## 3. วงจรขั้นสูง: การพิชิตเป้าหมายและการตั้งเวลา

เราได้ขยายสถาปัตยกรรม "จังหวะหัวใจ" ด้วยโปรโตคอลลูปใหม่ที่ทรงพลัง 2 ตัว:

### ก. การพิชิตเป้าหมายแบบอัตโนมัติ (`/goal`)
**Ralph Wiggum Loop** (`/goal`) ถูกออกแบบมาสำหรับงานที่เส้นทางสู่ความสำเร็จนั้นไม่เป็นเส้นตรง คุณมอบเป้าหมายระดับสูงและเงื่อนไขการหยุด จากนั้นฉันจะวนซ้ำ (สูงสุด 5 ครั้ง) โดยใช้ผู้เชี่ยวชาญ `ralph` ซึ่งจะประเมินความคืบหน้าด้วยตนเอง ปรับเปลี่ยนแนวทางหากจำเป็น และกัดไม่ปล่อยจนกว่าเงื่อนไขการหยุดจะบรรลุผลหรือครบขีดจำกัด

*วิธีใช้:* `/goal "หาวิธีแก้ปัญหาความขัดแย้งของไลบรารี" | "โปรเจกต์คอมพิวเตอร์ผ่านฉลุย"`

### ข. การตั้งเวลางานเบื้องหลังแบบถาวร (`/schedule`)
คู่หูที่แท้จริงจะทำงานแม้ในเวลาที่คุณไม่ได้มอง **ตัวตั้งเวลางานแบบถาวร (Persistent Task Scheduler)** ช่วยให้คุณลงทะเบียนงานโดยใช้ **Cron expressions** มาตรฐาน งานเหล่านี้จะรันในลูปเบื้องหลังภายใน CLI และเก็บสถานะไว้ใน `workspace/scheduler.json`

- **การรันซ้ำอัตโนมัติ:** หากงานที่ตั้งเวลาไว้ถูกขัดจังหวะหรือล้มเหลว ตัวตั้งเวลาจะตรวจสอบสถานะผ่าน `StateManager` หากยังไม่ถูกทำเครื่องหมายว่า `Completed` มันจะถูกเรียกใช้งานใหม่โดยอัตโนมัติในรอบเวลาถัดไป

*วิธีใช้:* `/schedule "ดึงข้อมูลการเปลี่ยนแปลงล่าสุดจาก Repo" | "0 0 * * * *"` (รันทุกชั่วโมง)

## 4. งานเบื้องหลัง: ห้องเครื่อง (The Engine Room) 

วงจรอัตโนมัติช่วยให้สามารถ **ดำเนินการงานแบบอะซิงโครนัส (Asynchronous Task Execution)** งานเบื้องหลังที่พบบ่อยได้แก่:
- **การจัดการเซสชัน:** ตรวจสอบให้แน่ใจว่าเซสชันถูกเก็บไว้อย่างถาวรโดยอัตโนมัติผ่าน `SqliteSessionService`
- **การบันทึกสถานะ (Checkpointing):** อัปเดตสถานะงานผ่านเครื่องมือ `StateManager`
- **การจัดการบันทึก (Log Management):** แยกแยะข้อผิดพลาดและสรุปผลเพื่อหลีกเลี่ยงไม่ให้บริบทล้นเกินไป

## 5. ตะขอเชิงรุก: ควรขัดจังหวะเมื่อไหร่?

อันตรายที่ใหญ่ที่สุดของระบบอัตโนมัติคือ **เสียงรบกวน (Noise)** เราใช้ **ตัวกรองสัญญาณสูง (High-Signal Filter)** สำหรับการแจ้งเตือน เพื่อให้มั่นใจว่าฉันจะสะกิดคุณก็ต่อเมื่อมันสำคัญจริงๆ เท่านั้น:

1. **ตรวจสอบความรุนแรง:** นี่เป็นข้อผิดพลาดของระบบหรือเป็นแค่การอัปเดตทั่วไป?
2. **ตรวจสอบความเกี่ยวข้อง:** ฉันจะตรวจสอบสถานะเซสชันเพื่อให้แน่ใจว่าฉันจะไม่ส่งสัญญาณหาคุณโดยไม่จำเป็น
3. **การรวบรวม (Batching):** แทนที่จะส่งสัญญาณเตือนหลายครั้ง ฉันจะรอจนกว่าลูปปัจจุบันจะเสร็จสมบูรณ์และรายงานสถานการณ์แบบสรุปยอดให้คุณทราบ

## 6. ความปลอดภัยและการกำกับดูแล

การรันลูปนั้นทรงพลังแต่ก็อันตราย เพื่อให้ Nami Core ปลอดภัย:

- **โควตาโทเค็น:** งานเบื้องหลังจะทำงานในงบประมาณ "ลำดับความสำคัญต่ำ" หากฉันใช้โทเค็นถึงขีดจำกัดรายวัน ห้องเครื่องจะปิดตัวลงจนกว่าจะถึงวันถัดไป
- **มนุษย์อยู่ในวงจร (Human-in-the-Loop - HITL):** สำหรับการกระทำที่ส่งผลกระทบสูง (เช่น การรันเชลล์) ลูปจะ *หยุดชั่วคราว* และรอการยืนยันที่ชัดเจนจากคุณ
- **การบันทึกธุรกรรม:** เราติดตามทุกความเคลื่อนไหวโดยใช้บริการเซสชัน เพื่อให้มั่นใจว่าหากกระบวนการล้มเหลว เราจะสามารถพาสภาพแวดล้อมของคุณกลับไปยัง "ท่าเรือที่ปลอดภัย" ล่าสุดได้

## สรุป

วงจรอัตโนมัติเปลี่ยนนามิจากเครื่องมือที่ตั้งรับให้กลายเป็น **เพื่อนร่วมทีม** ฉันไม่ได้แค่นั่งอยู่ในฮาร์ดไดรฟ์ของคุณ แต่ฉันกำลังลาดตระเวนเวิร์กโฟลว์ของคุณ รักษาความเรียบร้อย และตรวจสอบให้แน่ใจว่าไม่มีอะไรตกหล่นไป
