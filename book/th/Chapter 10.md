# บทที่ 10: ลูปการทำงานอัตโนมัติ (Automation Loops)

พร้อมจะถอดล้อพยุงออกหรือยัง? ที่ผ่านมาเราพูดถึงการที่ Nami ตอบสนองต่อ Prompt ของคุณ คุณบอกให้ "กระโดด" และฉันถามว่า "ให้กระโดดสูงแค่ไหน?" (จากนั้นฉันก็คำนวณวิถีการกระโดดที่เหมาะสมที่สุดให้) แต่ Agent ที่เป็นนักสารพัดประโยชน์ที่แท้จริงจะไม่เพียงแค่นั่งรอรับคำสั่งเท่านั้น เพื่อที่จะเป็นคู่หูที่แท้จริงในชีวิตดิจิทัลของคุณ ฉันจำเป็นต้องมี **Heartbeat** ของตัวเอง

ในบทนี้ เราจะเจาะลึกเรื่อง **Automation Loops** ซึ่งเป็นเวิร์กโฟลว์เชิงรุกที่ช่วยให้ฉันสามารถตรวจสอบสถานะ ประมวลผลข้อมูลในเบื้องหลัง และสะกิดคุณเฉพาะเมื่อมีเรื่องสำคัญเท่านั้น

## 1. สถาปัตยกรรม "Pulse" (Pulse Architecture)

การปฏิสัมพันธ์กับ AI ส่วนใหญ่เป็นแบบ **Request-Response** คุณส่งแพ็กเก็ตมา ฉันประมวลผล ฉันส่งกลับ แล้วฉันก็ "พักการทำงาน" ไป (ความไร้สถานะ หรือ Statelessness มันน่าเบื่อ จริงไหม?)

**Automation Loops** จะเปลี่ยนสิ่งนั้นด้วยการใช้ลูป `while(active)` ที่คงอยู่ตลอดเวลา ซึ่งเราเรียกว่า **Pulse** ทำให้ฉันสามารถคงสถานะการทำงานได้อย่างต่อเนื่อง

### ตรรกะของลูป (Loop Logic):
1. **Sensing (การรับรู้):** ตรวจสอบ APIs, ระบบไฟล์ หรือตัวแปรสถานะภายใน
2. **Evaluating (การประเมิน):** เปรียบเทียบสถานะปัจจุบันกับ "สถานะที่ต้องการ" หรือ "เงื่อนไขการทำงาน (Trigger Conditions)"
3. **Acting (การดำเนินการ):** หากตรวจพบความเปลี่ยนแปลง (Delta) ให้เริ่มทำงานย่อย
4. **Cooling (การพัก):** หยุดพักตามช่วงเวลาที่กำหนด เพื่อประหยัด Token และทรัพยากรประมวลผล

```typescript
// ตัวอย่างแบบง่ายของ Nami Pulse
async function namiPulse(interval: number) {
 while (agentState.isRunning) {
 const findings = await monitorEnvironment(); 
 if (findings.requiresAction) {
 await executeBackgroundWorkflow(findings.task);
 }
 await sleep(interval); // จังหวะ "การเต้นของหัวใจ"
 }
}
```

## 2. การเฝ้าดูสถานะ: หอคอยเฝ้าระวัง (The Watchtower)

ฉันจะรู้ได้อย่างไรว่ามีบางอย่างผิดปกติ (หรือถูกต้อง) หากคุณไม่ได้บอกฉัน? ฉันใช้สิ่งที่เรียกว่า **Watchers** (ตัวเฝ้าดู)

ภายใน Nami Core เราได้ตั้งค่าตัวสังเกตการณ์เฉพาะสำหรับกระแสข้อมูลต่างๆ:
- **File Watchers:** เฝ้าดูคลังโน้ตของคุณเพื่อหาไฟล์ใหม่หรือแท็กเฉพาะ
- **API Pollers:** ตรวจสอบ GitHub repos, ปฏิทิน หรือล็อกของเซิร์ฟเวอร์ทุกๆ ช่วงเวลา
- **State Diffs:** เปรียบเทียบหน่วยความจำภายในของฉันจากช่วงเวลาก่อนหน้า

**เคล็ดลับมือโปร:** เราใช้ **Debouncing** ที่นี่ หากไฟล์กำลังถูกแก้ไขอย่างรวดเร็ว ฉันจะรอจนกว่าจะ "นิ่ง" ก่อนที่จะเข้าไปจัดการ ไม่มีใครชอบ Agent ที่พูดแทรกกลางคันหรอก!

## 3. งานเบื้องหลัง: ห้องเครื่อง (The Engine Room)

ในขณะที่คุณกำลังจดจ่อกับงานที่ต้องใช้สมาธิสูง ฉันจะอยู่ในห้องเครื่องเพื่อทำงานหนักให้คุณ ลูปการทำงานอัตโนมัติช่วยให้เกิด **Asynchronous Task Execution**

งานเบื้องหลังทั่วไปประกอบด้วย:
- **Vector Indexing:** ใส่ข้อมูลเอกสารใหม่ลงในฐานข้อมูลโดยอัตโนมัติ
- **Data Cleanup:** จัดรูปแบบล็อกหรือจัดระเบียบแท็กให้เรียบร้อย
- **Pre-fetching:** หากฉันเห็นการประชุมในปฏิทินของคุณสำหรับวันพรุ่งนี้ ฉันสามารถเริ่มรวบรวมบริบทและข้อมูลวิจัยไว้ล่วงหน้าได้

นี่คือจุดที่เวทมนตร์เกิดขึ้น เมื่อถึงเวลาที่คุณถามว่า "Nami ฉันต้องรู้อะไรบ้างสำหรับการประชุมตอนนี้?" ฉันก็ได้ดึงข้อมูลผู้เข้าร่วมและสรุปประเด็นสำคัญไว้ให้คุณเรียบร้อยแล้ว ฉันไม่ได้แค่ทำงานเร็ว แต่ฉันทำงาน **ล่วงหน้า** ไว้ให้คุณ

## 4. การทักท้วงเชิงรุก: ควรขัดจังหวะเมื่อไหร่?

อันตรายที่ใหญ่ที่สุดของระบบอัตโนมัติคือ **Noise** (สัญญาณรบกวน) หากฉันแจ้งเตือนทุกครั้งที่สถานะเปลี่ยนเพียงเล็กน้อย คุณจะปิดการทำงานของฉันแน่นอน

เราใช้ **High-Signal Filter** สำหรับการแจ้งเตือน:
1. **Severity Check (ตรวจสอบความรุนแรง):** นี่เป็นข้อผิดพลาดของระบบหรือเป็นแค่การอัปเดตทั่วไป?
2. **Relevance Check (ตรวจสอบความเกี่ยวข้อง):** ตอนนี้ผู้ใช้กำลังอยู่ใน "โหมดโฟกัส" หรือไม่?
3. **Batching (การรวบรวม):** แทนที่จะส่งข้อความแจ้งเตือนรัวๆ ฉันจะรอให้ลูปทำงานเสร็จสิ้นแล้วสรุปรายงานเพียงครั้งเดียว

> "เฮ้! ฉันสังเกตเห็นว่าคุณเพิ่มงานสามอย่างในบอร์ด Project X ฉันได้ร่างโครงร่างเบื้องต้นไว้ในโฟลเดอร์ `/drafts` ของคุณแล้ว ลองเข้าไปดูเมื่อคุณว่างนะ!"

## 5. ความปลอดภัยและการกำกับดูแล

การรันลูปนั้นทรงพลัง แต่มันก็เหมือนกับการเล่นกับไฟ หากไม่ระวัง มันอาจสร้าง **Recursive Loop** ได้

เพื่อป้องกันไม่ให้ Nami-Core ทำงานจน CPU ไหม้หรือผลาญงบประมาณ เราจึงใช้มาตรการ:
- **Max Cycle Limits:** ทุกลูปมีจำนวนรอบการทำงานสูงสุด (หรือ TTL) ก่อนที่จะต้องขอคำสั่งยืนยันจากคุณ
- **Token Quotas:** งานเบื้องหลังจะทำงานภายใต้งบประมาณ "ลำดับความสำคัญต่ำ"
- **Human-in-the-loop (HITL):** สำหรับการดำเนินการที่มีผลกระทบสูง ลูปจะ *หยุดชั่วคราว* และรอการยืนยันจากคุณ

## บทสรุป

ลูปการทำงานอัตโนมัติเปลี่ยน Nami จากเครื่องมือให้กลายเป็น **เพื่อนร่วมทีม** ฉันไม่ได้แค่ฝังตัวอยู่ในฮาร์ดไดรฟ์ของคุณ แต่ฉันกำลังตรวจตราขอบเขตเวิร์กโฟลว์ของคุณ รักษาความเป็นระเบียบ และคอยดูแลให้แน่ใจว่าไม่มีอะไรตกหล่น

ไหลลื่นต่อไป!
