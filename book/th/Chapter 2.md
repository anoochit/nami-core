# บทที่ 2: วิศวกรรมแบบ AI-Native (AI-Native Engineering)

นักพัฒนา! ในโลกที่ทุกอย่างหมุนไปเร็ว เราไม่ได้แค่สร้างแอปฯ ขึ้นมา แต่มันคือการเปลี่ยนผ่านกระบวนทัศน์ครั้งใหญ่! 

## เป็นมากกว่าแค่ตัวห่อหุ้ม
ในยุคแรกๆ ของการรวม LLM เข้ากับระบบ ซอฟต์แวร์ถูกออกแบบมาให้เป็นเพียง "ตัวห่อหุ้ม" (wrapper) รอบๆ พรอมต์ (prompt) เท่านั้น แต่ **วิศวกรรมแบบ AI-Native** คือการเปลี่ยนผ่านที่แท้จริง โดยที่ LLM ไม่ได้เป็นแค่ฟีเจอร์ที่ถูกแปะเพิ่มเข้ามา แต่มันคือหัวใจหลักที่ขับเคลื่อนกลไกการใช้เหตุผลของระบบ!

### วงจรการใช้เหตุผล (The Reasoning Loop)
ซอฟต์แวร์แบบดั้งเดิมมักเดินตามตรรกะ if-then-else ที่แข็งทื่อและตายตัว แต่ระบบ AI-native ของเราทำงานผ่าน **วงจรการใช้เหตุผลที่ยืดหยุ่น** ดังนี้:
1. **การรับรู้ (Perception):** การอ่านเจตจำนงของคุณควบคู่ไปกับสภาพแวดล้อมจริง (วิกิ, ไฟล์, ระบบ)
2. **การวางแผน (Planning):** การย่อยเป้าหมายที่ซับซ้อนให้กลายเป็นการเรียกใช้เครื่องมือ (tool calls) ที่ทำได้จริง
3. **การดำเนินการ (Execution):** การส่งพลังให้เครื่องมือเฉพาะทาง (MCP, Shell, Web Search) โต้ตอบกับโลกภายนอก
4. **การสะท้อนคิด (Reflection):** การประเมินผลลัพธ์และปรับเปลี่ยนแผนอย่างชาญฉลาดในแบบเรียลไทม์!

### การออกแบบเพื่อรองรับความไม่แน่นอน
ระบบ AI-native ถูกสร้างขึ้นมาเพื่อให้เข้าใจว่าโลกนี้มีความสุ่ม (non-deterministic) อยู่เสมอ ดังนั้นเราจึงต้องมี:
- **โครงสร้างข้อมูลที่เข้มงวด (Strict Schemas):** ใช้ JSON และสกีมาที่ชัดเจนในการสั่งการเครื่องมือ
- **การจัดการบริบท (Context Management):** การคัดกรองและจัดลำดับความสำคัญของข้อมูลแบบอัจฉริยะ เพื่อให้สิ่งที่สำคัญที่สุดอยู่ตรงหน้าหน้าต่างบริบทเสมอ!
- **ความสามารถในการตรวจสอบ (Verifiability):** การสร้างเครื่องมือให้เอเจนท์สามารถย้อนกลับมาตรวจสอบงานของตัวเองได้จริง!

### แนวทางของ Nami
Nami ถูกสร้างขึ้นบนหลักการเหล่านี้ เราใช้ "คลังวิกิ" (Wiki vault) เป็นบริบทที่มีชีวิตที่ฉันสามารถสอบถามและอัปเดตได้แบบเรียลไทม์ ก้าวข้ามโครงสร้างข้อมูลแบบเดิมๆ ที่หยุดนิ่ง ให้กลายเป็นระบบที่โตไปพร้อมกับคุณ!
