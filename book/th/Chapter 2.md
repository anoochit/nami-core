# บทที่ 2: วิศวกรรมแบบ AI-Native (AI-Native Engineering)

## เป็นมากกว่าแค่ตัวห่อหุ้ม
ในยุคแรกๆ ของการรวม LLM เข้ากับระบบ ซอฟต์แวร์ถูกออกแบบมาให้เป็นเพียง "ตัวห่อหุ้ม" (wrapper) รอบๆ พรอมต์ (prompt) วิศวกรรมแบบ AI-Native คือการเปลี่ยนผ่านกระบวนทัศน์ที่ LLM ไม่ได้เป็นเพียงฟีเจอร์ที่ถูกเพิ่มเข้ามา แต่เป็นหัวใจหลักของกลไกการใช้เหตุผลในระบบ

### วงจรการใช้เหตุผล (The Reasoning Loop)
ซอฟต์แวร์แบบดั้งเดิมทำตามตรรกะ if-then-else ที่ตายตัว แต่ระบบ AI-native จะใช้วงจรการใช้เหตุผล:
1. **การรับรู้ (Perception):** การอ่านเจตจำนงของผู้ใช้และสภาพแวดล้อมปัจจุบัน (วิกิ, ไฟล์, ระบบ)
2. **การวางแผน (Planning):** การย่อยเป้าหมายที่ซับซ้อนออกเป็นการเรียกใช้เครื่องมือ (tool calls) ที่สามารถดำเนินการได้จริง
3. **การดำเนินการ (Execution):** การใช้เครื่องมือเฉพาะทาง (MCP, Shell, Web Search) เพื่อโต้ตอบกับโลกภายนอก
4. **การสะท้อนคิด (Reflection):** การประเมินผลของการกระทำและปรับเปลี่ยนแผนอย่างยืดหยุ่น

### การออกแบบเพื่อรองรับความไม่แน่นอน
ระบบ AI-native จะต้องถูกสร้างขึ้นเพื่อรองรับผลลัพธ์ที่เป็นแบบสุ่มหรือไม่แน่นอน (non-deterministic) ซึ่งสิ่งนี้ต้องการ:
- **โครงสร้างข้อมูลที่เข้มงวด (Strict Schemas):** การใช้ JSON และคำจำกัดความที่มีโครงสร้างสำหรับการโต้ตอบกับเครื่องมือ
- **การจัดการบริบท (Context Management):** การคัดกรองและจัดลำดับความสำคัญของข้อมูลเพื่อให้เหมาะสมกับหน้าต่างบริบท (context windows)
- **ความสามารถในการตรวจสอบ (Verifiability):** การสร้างเครื่องมือที่ช่วยให้เอเจนท์สามารถตรวจสอบงานของตัวเองได้ (เช่น การตรวจสอบว่าไฟล์ถูกเขียนอย่างถูกต้องจริงๆ หรือไม่)

### แนวทางของ Nami
Nami ถูกสร้างขึ้นบนหลักการเหล่านี้ โดยใช้คลังวิกิ (Wiki vault) เป็นบริบทที่มีชีวิตชีวา ซึ่งตัวประมวลผลสามารถสอบถามและอัปเดตได้แบบเรียลไทม์ ก้าวข้ามโครงสร้างข้อมูลแบบเดิมที่หยุดนิ่ง
