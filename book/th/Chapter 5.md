# บทที่ 5: ความจำระยะยาว – คลังวิกิ (The Wiki-Vault)

เอาละทุกคน! ระบบพร้อมทำงานเต็มที่ (System check is green) เราคุยกันเรื่อง Flow และ Logic ไปแล้ว แต่ตอนนี้ถึงเวลาต้องพูดเรื่อง **ความคงทนของข้อมูล (Persistence)** กันบ้าง ถ้าเราจำสิ่งที่สร้างไว้เมื่อวานไม่ได้ เราก็เหมือนกำลังย่ำอยู่กับที่ในโคลนตม

ใน **Nami Core** ความจำไม่ใช่แค่ข้อมูลที่ถูกบันทึกในฐานข้อมูล แต่มันคือระบบไฟล์ที่มีชีวิตและลมหายใจ ขอต้อนรับสู่ **Wiki-vault (คลังวิกิ)**

## 1. โฟลเดอร์ `wiki/`: นีโอคอร์เท็กซ์ (Neocortex) ส่วนขยายของเรา

ในสถาปัตยกรรมของ Nami โฟลเดอร์ `wiki/` คือราชาผู้ไร้คู่แข่งของความจำระยะยาว ในขณะที่ `logs/` บอกเราว่าเกิดอะไรขึ้น *ไปแล้ว* แต่ `wiki/` จะบอกเราว่าสิ่งต่าง ๆ คือ *อะไร* และมัน *ทำงานอย่างไร*

คิดซะว่ามันคือสถานะที่คงอยู่ (Persistent state) ของระบบ เมื่อผม (เอเจนต์) หรือคุณ (มนุษย์) เรียนรู้บางอย่างที่สำคัญต่อภารกิจ (Mission-critical) ไม่ว่าจะเป็นลูกเล่นเฉพาะของ API, กระบวนการ Deployment หรือข้อตกลงการตั้งชื่อเฉพาะโปรเจกต์ ข้อมูลนั้นจะไม่จางหายไปในประวัติการแชทที่จะถูกลบออกในที่สุด **แต่มันจะถูกยกระดับขึ้นสู่ Wiki**

### ทำไมต้องใช้ Obsidian Markdown?
เราใช้ Markdown รูปแบบ Obsidian เพราะมันเชื่อมช่องว่างระหว่างการอ่านของเครื่อง (Machine-readability) และสัญชาตญาณของมนุษย์:
- **การเชื่อมโยงสองทิศทาง (Bi-directional Linking):** `[[Linked Notes]]` ช่วยให้เราสร้างกราฟความรู้ (Graph of knowledge) ได้
- **YAML Frontmatter:** ช่วยให้ผมมี Metadata ที่เป็นโครงสร้าง เพื่อการกรองและสืบค้นข้อมูลผ่านโปรแกรมได้อย่างแม่นยำ
- **พกพาสะดวก (Portability):** มันก็แค่ไฟล์ธรรมดา ไม่มีการผูกขาดกับฐานข้อมูลที่เป็นความลับทางการค้า (Proprietary) ถ้าเกิดเหตุขัดข้อง เราก็ยังมีข้อมูลที่เป็นข้อความเหล่านี้อยู่

## 2. โปรโตคอล "เช็ก Wiki ก่อน Google"

นี่คือกฎเหล็กของ Nami Core ถ้าคุณจะจำอะไรไปจากบทนี้สักอย่าง ขอให้เป็นสิ่งนี้: **เช็ก Wiki ภายในก่อนจะเริ่มค้นหาในอินเทอร์เน็ต**

### ทำไมล่ะ?
1. **บริบทคือหัวใจสำคัญ (Context is King):** Google รู้ว่า *โลก* เขียน React ยังไง แต่ Wiki รู้ว่า *เรา* เขียน React สำหรับกรณีเฉพาะ (Edge-case) ของเรายังไง
2. **ความรวดเร็วและลดเสียงรบกวน (Latency & Noise):** โปรแกรมค้นหาทั่วไปมีข้อมูลขยะเยอะมาก แต่ Wiki คือสภาพแวดล้อมที่เต็มไปด้วยข้อมูลที่มีคุณภาพ (High-signal) ซึ่งปรับแต่งมาเพื่อเครื่องมือ (Stack) ของเราโดยเฉพาะ
3. **ป้องกันการหลงลืม (Prevention of Drift):** ถ้าเราแก้บั๊กไปครั้งหนึ่งแล้วและบันทึกไว้ใน Wiki เราก็ไม่ต้องไป "ค้นหาซ้ำ" เพื่อหาวิธีแก้เดิมผ่าน Google อีก

**ลำดับขั้นตอนของโปรโตคอล (The Protocol Flow):**
1. **คำถาม (Query):** "ฉันจะเปลี่ยน API keys ได้อย่างไร?"
2. **ตรวจสอบ (Scan):** เช็กที่ `wiki/Operations/Security.md`
3. **ลงมือ (Execute):** ทำตามขั้นตอนภายในที่ระบุไว้
4. **สำรอง (Fallback):** จะไปค้นหาจากเว็บภายนอกต่อเมื่อใน Wiki ไม่มีการระบุไว้เท่านั้น
5. **อัปเดต (Update):** เมื่อพบคำตอบจากภายนอกแล้ว **จงนำความรู้นั้นกลับมาที่บ้าน** และบันทึกใน Wiki ทันที

## 3. การยกระดับความรู้ (วงจรการเรียนรู้)

ความจำระยะยาวจะมีประโยชน์ก็ต่อเมื่อมันถูกต้องแม่นยำ ใน Nami Core เราใช้กระบวนการที่เรียกว่า **การยกระดับความรู้ (Knowledge Promotion)**:

- **ระดับ 1: ชั่วคราว (แชท):** แลกเปลี่ยนไอเดียและปรึกษาหารือ
- **ระดับ 2: บันทึก (Logs):** บันทึกการตัดสินใจที่เกิดขึ้น
- **ระดับ 3: ถาวร (Wiki):** รูปแบบที่พิสูจน์แล้ว, โครงสร้างสถาปัตยกรรม และเอกสาร "แหล่งข้อมูลอ้างอิงหลัก" (Source of Truth) จะถูกทำให้เป็นมาตรฐานที่นี่

ในขณะที่ผมปฏิบัติหน้าที่เป็นเอเจนต์ของคุณ ผมจะคอยมองหาช่วงเวลาที่ "ควรค่าแก่การลง Wiki" อยู่เสมอ ถ้าเราใช้เวลา 30 นาทีในการดีบั๊กปัญหาเครือข่าย Docker ที่แปลกประหลาด งานสุดท้ายของผมไม่ใช่แค่การแก้โค้ด แต่เป็นการร่างไฟล์ `wiki/DevOps/Docker-Network-Fix.md` ขึ้นมา

## 4. การจัดโครงสร้างคลังข้อมูลเพื่อการสืบค้น

เพื่อให้หน่วยความจำมีประสิทธิภาพ เราจะทำตามโครงสร้างการจัดหมวดหมู่ที่เคร่งครัดภายในรากของ `wiki/`:

- `/atlas`: แผนผังเนื้อหา (Maps of Content - MOCs) ที่เชื่อมโยงไปยังโฟลเดอร์ย่อยต่าง ๆ
- `/specs`: รายละเอียดทางเทคนิค (Technical specifications) สำหรับโปรเจกต์ปัจจุบัน
- `/guides`: คู่มือสอนการใช้งานแบบเป็นขั้นตอนสำหรับวงจรการทำงานระหว่างมนุษย์และเอเจนต์
- `/archive`: ความรู้ที่ล้าสมัย (ห้ามลบเด็ดขาด ให้ย้ายมาที่นี่แทน)

## 5. การนำไปใช้ทางเทคนิค: พร้อมสำหรับ RAG (RAG-Ready)

การเก็บความจำระยะยาวไว้ในรูปแบบ Markdown ที่สะอาดและรองรับ YAML ทำให้เราอยู่ในสถานะ "พร้อมสำหรับ RAG" (Retrieval-Augmented Generation) ผมสามารถประมวลผลไฟล์เหล่านี้ แปลงเป็น Vector และดึงข้อมูลเข้าสู่บริบท (Context window) ของผมได้อย่างแม่นยำระดับผ่าตัด

เมื่อคุณถามคำถามผม ผมจะไม่แค่ "เดา" จากข้อมูลที่ถูกฝึกสอนมาเท่านั้น แต่ผมจะทำการค้นหาเชิงความหมาย (Semantic search) ในโฟลเดอร์ `wiki/` เพื่อให้คำตอบที่ตั้งอยู่บนพื้นฐานของ **ความเป็นจริงของเรา**

### การตรวจสอบตรรกะสุดท้าย (Final Logic Check)

โฟลเดอร์ `wiki/` ไม่ใช่สุสานสำหรับเก็บโน้ต แต่มันคือ **เครื่องยนต์หลักที่ขับเคลื่อนความฉลาดของเรา** การให้ความสำคัญกับ "Wiki ก่อน Google" จะทำให้เรามั่นใจได้ว่าทุกชั่วโมงที่เสียไปกับการทำงานจะทำให้ระบบฉลาดขึ้น เร็วขึ้น และเป็นอิสระมากขึ้น

**มาเริ่มลุยกันเลย ความรู้คือพลัง แต่ความรู้ที่มีการบันทึกไว้อย่างดีคือแรงขับเคลื่อนที่ไม่มีวันหยุด!**
