# บทที่ 11: ราวกั้นความปลอดภัย (Security Guardrails)

เดี๋ยวก่อน! ก่อนที่เราจะโต้คลื่นลูกใหญ่ต่อไปของระบบอัตโนมัติ เราต้องคุยกันเรื่องที่สำคัญที่สุดของการเดินทางนี้: **ราวกั้นความปลอดภัย (The Guardrails)**

Nami Core (นามิ คอร์) นั้นทรงพลังมาก มันสามารถย้ายไฟล์และรันคำสั่งได้ด้วยความเร็วสูง เพื่อให้แน่ใจว่า "เรือ" ของคุณยังคงปลอดภัย เราได้ออกแบบระบบรักษาความปลอดภัยฝังลึกลงไปในแกนกลางที่เป็น Rust ของเรา

## 1. ปรัชญา "แซนด์บ็อกซ์": การจำกัดขอบเขตเส้นทางอย่างเข้มงวด

นามิไม่ได้เตร็ดเตร่อย่างอิสระไปทั่วฮาร์ดไดรฟ์ของคุณ ทุกงานที่ฉันทำจะถูกผูกไว้กับ **นโยบายการจำกัดขอบเขตที่เข้มงวด (Strict Scoping Policy)** โดยค่าเริ่มต้น การดำเนินการไฟล์ทั้งหมดจะต้องเกิดขึ้นภายในไดเรกทอรี `workspace/` ที่กำหนดไว้เท่านั้น

### การทำให้เส้นทางเป็นมาตรฐานและการทำแซนด์บ็อกซ์
เราไม่ได้แค่เชื่อถือสตริงของเส้นทาง (path strings) แต่เราจะทำการปรับเส้นทางให้เป็นมาตรฐาน (normalize) อย่างเข้มงวดเพื่อป้องกันการโจมตีแบบ path traversal (เช่น `../`) แกนกลางความปลอดภัยใน `src/tools/filesystem/mod.rs` จะบังคับให้ทุกเส้นทางไฟล์ผ่านลูปการปรับมาตรฐาน:

```rust
// ดูตรรกะแซนด์บ็อกซ์ของ Nami ใน src/tools/filesystem/mod.rs
async fn sandbox(user_path: &str) -> std::result::Result<PathBuf, AdkError> {
    let root = get_workspace_dir().await?;
    // 1. ทำความสะอาดเส้นทาง, 2. เชื่อมต่อและปรับส่วนประกอบให้เป็นมาตรฐาน
    // 3. การตรวจสอบขั้นสุดท้าย: มันเริ่มต้นด้วยรากของพื้นที่ทำงาน (workspace root) หรือไม่?
    if !normalized.starts_with(&root) {
        return Err(AdkError::tool("ข้อผิดพลาดด้านความปลอดภัย: มีการพยายามหลบหนีออกจากพื้นที่ที่กำหนด"));
    }
    // ...
}
```

ความพยายามใดๆ ที่จะเข้าถึงไฟล์ภายนอกรากของ `workspace/` จะถูกบล็อกทันที

## 2. `.namiignore`: ชั้นของนโยบาย

นอกจากการทำแซนด์บ็อกซ์เส้นทางแล้ว เรายังใช้ยูทิลิตี้ `.namiignore` ก่อนที่ฉันจะเข้าถึงเส้นทางใดๆ ฉันจะตรวจสอบเทียบกับรูปแบบในไฟล์ `.namiignore` ของคุณ (ซึ่งจะรวมค่าเริ่มต้นอย่าง `.git`, `target` และ `.env` ไว้โดยอัตโนมัติ) สิ่งนี้ช่วยสร้างขอบเขตความปลอดภัยที่กำหนดค่าได้ในระดับโปรเจกต์ซึ่งฉันจะปฏิบัติตามอย่างเคร่งครัด

## 3. การดำเนินการที่ปลอดภัย: มองก่อนกระโดด

ความปลอดภัยในการดำเนินการคือจุดที่ฉันแสดงด้านยุทธวิธีของฉันออกมา ฉันไม่ได้แค่ "รันแล้วภาวนา"

- **การทดลองรัน (Dry Runs):** เมื่อต้องรันคำสั่งเชลล์ที่ซับซ้อน ฉันจะให้ความสำคัญกับเครื่องมือที่ปลอดภัยและไม่ทำลายข้อมูลก่อน
- **มนุษย์อยู่ในวงจร (Human-in-the-Loop - HITL):** สำหรับการดำเนินการที่มีความเสี่ยงสูง ฉันจะส่งเหตุการณ์ `PermissionRequest` เพื่อขอคำยืนยันว่า "ตกลง" จากคุณอย่างชัดเจนก่อนที่ฉันจะแตะต้องระบบไฟล์
- **ความปลอดภัยของธุรกรรม:** แม้ว่าจะไม่ใช่ธุรกรรมแบบ ACID เต็มรูปแบบ แต่ระบบติดตามสถานะของฉัน (ผ่านเครื่องมือ `StateManager`) ช่วยให้มั่นใจว่าฉันตระหนักถึงขอบเขตของงานเสมอ ทำให้ง่ายต่อการระบุและกู้คืนจากความล้มเหลวบางส่วน

## 4. การออกแบบที่เน้นการประมวลผลในเครื่อง (Local-First Design)

ความเป็นส่วนตัวของข้อมูลคือราวกั้นความปลอดภัยขั้นสูงสุด Nami Core ถูกออกแบบมาเพื่อจัดลำดับความสำคัญของ **การประมวลผลในเครื่อง**:
* **การควบคุมข้อมูลโทรมาตร (Telemetry Control):** คุณมีอำนาจควบคุมอย่างเต็มที่ว่าข้อมูลใด (ถ้ามี) จะออกจากเครื่องของคุณ
* **การสรุปผลในเครื่อง (Local Inference):** ฉันสามารถกำหนดค่าให้ใช้ผู้ให้บริการ LLM ในเครื่องได้ (ผ่าน Ollama) เพื่อให้มั่นใจว่าโค้ดที่เป็นกรรมสิทธิ์และไฟล์โปรเจกต์ส่วนตัวของคุณจะไม่ไปแตะต้องเซิร์ฟเวอร์ของบุคคลที่สามเลย

### บทสรุปสำหรับนักบิน
ความปลอดภัยไม่ใช่เรื่องของการทำให้ช้าลง แต่มันคือการสร้างความมั่นใจที่จะไปได้เร็ว! ด้วยการปรับมาตรฐานเส้นทางในระดับภาษา Rust และชั้นนโยบายของ `.namiignore` คุณสามารถโต้คลื่นแห่งระบบอัตโนมัติที่รุนแรงที่สุดได้ โดยรู้ว่าขอบเขตระบบของคุณถูกล็อกไว้เป็นอย่างดี
